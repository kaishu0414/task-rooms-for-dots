# Task Rooms for Dots

**自分の dot とのやり取りを、タスクごとに整理する、dot 向けの個人用アプリの雛形です。**

「どの仕事の話だったか」「次に何をするか」「添付した画像はどれか」を、タスク単位で見返せるようにします。利用者は、それぞれ自分の ChatGPT アカウントで自分専用のアプリを作ります。

## まず、自分の dot にこの一文と URL を渡す

導入する人が、**自分自身の dot** に送ります。作者の dot や X の返信欄へ送る文章ではありません。

```text
このリポジトリの AGENT_SETUP.md を読み、実行前に安全確認して、私専用の非公開 Task Rooms for Dots を導入して。工程数・完了数・今の作業・待ち理由を途中で知らせ、導入後は私の端末でのアプリ追加を案内して。
<PUBLIC_REPOSITORY_URL>
```

公開 GitHub URL はまだ未設定です。`<PUBLIC_REPOSITORY_URL>` を実際の URL に置き換えてください。[コピーする文だけを開く](COPYPASTE_INSTALL_PROMPT.md)。秘密鍵や個人情報は追記しません。

あとは dot が [導入手順](AGENT_SETUP.md)を読み、安全確認から案内します。ログインや権限承認など、本人の操作が必要なところでは止まって説明します。使える機能にはアカウント差があり、貼り付けるだけでの導入完了は保証していません。

### 作業中は「7 工程のうち何工程まで」を確認できます

本体の導入は、安全確認 → 利用条件 → ローカル検査 → 非公開 Site → 接続と一往復 → 使う端末で確認 → 引き渡し、の 7 工程です。dot は有意な進捗や待ち状態の変化を伝え、長い作業中は実行環境が許す範囲で数分ごとの状況報告を目安にします。

```text
本体 3/7 工程完了｜実施中：4. 非公開 Site の準備
今：初回デプロイの結果を確認しています。
待ち：サービス側の処理待ち。今のところ操作は不要です。
次：本人のログインと、この Site の所有者設定を確認します。
```

完了数は確認できた工程の数で、経過時間の割合ではありません。導入時間は環境で変わり、残り時間や固定間隔の報告は保証していません。承認・ログイン待ちは作業中と区別し、未確認の工程は完了に数えません。自動返信・通知・履歴取り込みは、希望と必要な承認を確認してから別枠で進めます。

### スマートフォン・PC への追加は、導入後に dot が案内します

手順の置き場は [ホーム画面・デスクトップへの追加](docs/PWA.md)です。dot が使う端末とブラウザーを確認し、該当する手順だけを伝えます。追加するのは **作成した自分用 Site** で、GitHub のページではありません。追加せずブラウザーで使う方法も選べます。通知の有効化は別の任意設定です。

別の利用者の環境で試すときは、[初回導入テスト](docs/FIRST_RUN_TEST.md)に結果を残せます。この配布物の別アカウントでの導入と、各端末へのアプリ追加は未検証です。

## 自分の dot と育てる入口

導入後は、自分の dot に相談しながら、画面・表示名・整理のしかたを自分用に変更できます。MIT ライセンスで改変・商用利用が可能です。認証、非公開の保存領域、秘密の分離を弱める変更は避け、変更のたびに検査してください。ChatGPT / Sites / プラグイン等が利用できるアカウントが前提で、すべてのアカウントで導入できるとは限りません。

基本機能は、タスク別の会話、状態別の一覧、画像添付、リアクション、過去ページの参照、自分の dot との接続です。選択した過去会話の要約取り込み、イベント連携、端末通知は任意の追加設定です。

## 何が変わる？

普段の dot との会話に、仕事ごとの整理場所を加えます。タスク別のやり取り、次のアクション、添付をまとめるための画面です。

**タスクを分けても、独立した AI や別々の ChatGPT 会話が増えるわけではありません。** dot の記憶や権限、AI 側の会話文脈をタスク間で分離する仕組みでもありません。機密区分の違う情報を隔離する用途には使わないでください。

## まず知っておいてほしいこと

- これは完成済みの共有サービスや、ワンクリックで使える配布プラグインではありません。
- 作者の dot、既存アプリ、会話、保存データへの接続は含みません。
- 各利用者が **新しい非公開 Site・空のデータベース・空の画像ストレージ・自分のプラグイン** を用意します。イベント購読を使う場合も自分専用に設定します。
- 公開するのはコードの雛形です。自分が使うアプリやデータを公開する必要はありません。
- この配布物を別の利用者のアカウントへ導入する実地試験は未実施です。認証・購読・返信は、導入先で確認してください。

個人アカウントの Site-hosted plugin は、現在、他の利用者へ招待や共有リンクで直接配布できません。そのため、この雛形を各人が自分用に導入する方式を採っています。Site の URL を共有するだけでもプラグインは共有されません。[OpenAI のプラグイン導入案内](https://help.openai.com/en/articles/20001547-hosting-a-plugin-with-chatgpt-sites)

## 確認済みのことは、検証結果で確かめる

実施した検査と未確認の範囲は [TEST_REPORT.md](TEST_REPORT.md) に分けています。テストの成功や動作確認だけで、応答速度、大量データでの性能、すべての端末での快適さを保証するものではありません。

## 開発者向けのローカル確認

初めて取得したコードは、[実行前の安全確認](docs/SECURITY_REVIEW.md)を済ませてください。その後、Node.js 22.13.0 以降を用意し、リポジトリのルートで実行します。これらのコマンドは、GitHub への送信や Site の作成・公開を行いません。

```sh
npm ci --ignore-scripts
npm test
npm run typecheck
npm run build
npm run validate:release
npm run setup:check
```

依存パッケージのインストール時スクリプトは、既定で無効にします。必要になった場合も、個別に内容と必要性を確認してから対応し、一括許可で警告を回避しません。

ローカルの検査が通っても、ChatGPT との接続完了を意味しません。実行条件と確認範囲は[導入ガイド](docs/SETUP.md)を参照してください。

`validate:release` は未変更の配布物を照合する検査です。自分用の設定を追加した運用コピーや、コードを変更したコピーでは、変更・私的な設定を検出して失敗する場合があります。

## データを公開しないために

配布物には、運用中のデータベース、実際の画像、会話ログ、接続済みの設定、秘密鍵を入れない方針です。例に使う内容は架空です。利用開始後に入力する内容は、自分の Site のデータとして別途管理します。

`.env`、実際のホスティング設定、ログ、バックアップ、スクリーンショットを公開リポジトリに追加しないでください。自動検査だけで漏えいゼロは保証できないため、公開前にはファイル一覧と中身を目でも確認します。

公開・導入時の具体的な停止条件は[リスクと確認ゲート](docs/DEPLOYMENT_CHECKLIST.md#リスクと確認ゲート)を参照してください。

詳しくは[データと画像の扱い](docs/PRIVACY.md)、[セキュリティ方針](SECURITY.md)をご覧ください。

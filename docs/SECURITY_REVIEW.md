# インストール前に、コードを読んで確認する

**最初にコードを読む。インストールや実行はその後です。** 公開リポジトリであることや、以前の検査に通ったことだけを根拠に、手元の版も安全だとは判断しません。

## dot に依頼する確認範囲

1. 取得元と対象の版を確認します。コミット ID、または取得したアーカイブのハッシュを控え、途中で別の版に変わった場合は見直します。
2. 全ファイル一覧を確認し、ソース、設定、`package.json`、ロックファイル、実行スクリプト、ビルド設定を読みます。インストール時に走る処理や、外部から別のプログラムを取得して実行する箇所を確認します。
3. 依存パッケージの名前・版・取得元を確認します。利用可能な検査手段で既知の脆弱性も確認し、検査できなかった範囲は残します。
4. 認証と認可を読みます。Sites の信頼できる本人情報を使い、未設定・未認証・別人のときに拒否するかを確認します。
5. DB、R2、イベント callback、Push など、データの保存先と送信先を一覧にします。不要な解析・追跡・外部送信、秘密の出力がないか確認します。
6. 画像取得、入力検証、重複処理防止、購読の停止、履歴取り込みを読みます。任意の URL への送信や、未確認の本人投稿への書き換えがないか確認します。

付属の検査スクリプトも最初は検査対象です。`validate:release` を含め、内容を読まずに「検査用だから」と実行しないでください。静的確認前には、インストール、ビルド、Site の作成・デプロイ、秘密の登録を進めません。

ソースや設定を外部のスキャンサービスへアップロードしないでください。依存パッケージの名前と版だけを既知の脆弱性情報へ照会する場合も、送る項目と照会先を確認します。

## 短い結果を見てから次へ進む

結果は次の形で受け取ります。

```text
対象の版：確認したコミットまたはアーカイブのハッシュ
読んだ範囲：コード・依存関係・認証・外部送信など
見つかった懸念：重大度と根拠
未確認：本番の権限、他アカウント、端末動作など
判断：次へ進める／修正や確認が必要なので停止
```

重大な懸念、説明できない外部送信、取得元の不一致があれば、Site の作成やスクリプト実行を止めます。判断できない箇所は、そのまま安全だと決めつけません。

スキャンはマルウェアや脆弱性がないことの証明ではありません。コードの静的確認、依存関係の確認、自動テスト、本番の認証・動作確認は、それぞれ異なる検査です。何を確認したかを具体的に記録します。

この確認を終えてから [SETUP.md](SETUP.md) へ戻り、自分と dot の表示名、自分専用 Site の設定を進めます。

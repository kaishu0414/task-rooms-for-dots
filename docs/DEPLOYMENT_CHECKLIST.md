# 導入・公開前のチェックリスト

チェックは、実際に確認してから付けてください。ローカルテストが通っただけの項目や、未確認の別アカウント・端末の動作は、完了にしません。

## 配布するコードに個人情報を入れない

- [ ] 新しい配布用フォルダーだけを対象にしている。運用中アプリのフォルダーや Git 履歴を流用していない。
- [ ] 実名、会社名、メール、個人の URL、実際の Site / plugin / subscription の識別子が入っていない。
- [ ] 会話、タスク、業務数値、実画像、画像のメタデータ、内部メモ、データベースのコピーが入っていない。
- [ ] `.env`、秘密鍵、接続先入りの `.openai/hosting.json`、ログ、バックアップ、依存パッケージの実体、ビルド生成物を配布対象から外した。
- [ ] テストデータと説明例は架空の内容だけ。画面写真を載せる場合も、空の環境と架空データから作った。
- [ ] `npm test`、`npm run typecheck`、`npm run build`、`npm run validate:release` の結果を確認した。
- [ ] 自動検査の後、配布予定の全ファイル名と本文を目視した。
- [ ] リリース用アーカイブも展開して再確認した。フォルダーの検査結果だけで済ませていない。
- [ ] README に書く実施済み・未実施の範囲が、実際の結果と一致している。
- [ ] MIT の LICENSE と、第三者のコード・依存パッケージのライセンス表記を確認した。
- [ ] GitHub の作成・push・公開範囲の変更は、所有者の許可がある段階でだけ実施する。

## 自分用の環境を、他人の環境から切り離す

- [ ] インストール前に全ファイル一覧、ソース、設定、依存関係、スクリプトを読み、対象の版と安全確認の範囲を記録した。
- [ ] 重大な懸念や不審な外部送信を残したまま、実行・秘密登録・デプロイを進めていない。
- [ ] 自分と dot の表示名は自分用の環境だけに設定した。表示名を本人確認に使っていない。
- [ ] 新しい Site の所有者が自分で、公開範囲は所有者限定になっている。
- [ ] D1 の `DB` と R2 の `BUCKET` は新しい空の保存領域で、スキーマ以外のデータを移していない。
- [ ] 実際の `.openai/hosting.json` は自分用の作業コピーだけにある。
- [ ] 初回は `mcp` を宣言せず、所有者メールを設定して、本人 ID 確認用の非公開デプロイを行った。
- [ ] `TASKROOM_OWNER_EMAIL` と `TASKROOM_OWNER_USER_ID` を、安全なサーバー側設定に登録した。
- [ ] 自分の Site で得た ID を使っており、別の Site の所有者 ID をコピーしていない。
- [ ] 初回の `/api/setup/identity` は、設定済みメールと一致する認証済み本人だけが使える。未設定の間は通常のタスク・画像・MCP にアクセスできない。
- [ ] サインインしていない状態では、タスク・メッセージ・画像・MCP ツールを読めない。
- [ ] 所有者とは異なる認証情報を拒否するテストが通る。実アカウントで未確認なら、その旨を残した。
- [ ] ブラウザーの入力だけで本人確認を偽装できない。Sites を迂回する公開の直通経路がない。

## 自分の dot と一往復できる

- [ ] 所有者メールと Site 内ユーザー ID の設定後に `mcp` を追加し、同じ Site を非公開のまま再デプロイした。
- [ ] 自分の Site が作ったプラグインを Install / Connect した。作者や他人のプラグインではない。
- [ ] `list_tasks` で、新しいアプリの内容だけが返る。
- [ ] `user_message.created` がイベント一覧に出る。
- [ ] 正規の購読処理で渡された callback の HTTPS オリジンを確認し、必要な宛先だけ許可した。
- [ ] callback の署名付き検証が成功してから購読が有効になる。検証失敗時に本文や画像を送らない。
- [ ] 架空のタスクへ投稿すると、自分の dot が `get_task_thread` で該当タスクを読める。
- [ ] 読み取った元投稿が `role: "user"`、`authorVerified: true`、`historicalSummary: false` で、投稿者 ID がこの Site の自分に一致する。
- [ ] `get_task_thread` による読み取りだけでは、投稿が返信済みに変わらない。
- [ ] `reply_to_message` による返信が同じタスクに表示され、元投稿とひも付く。
- [ ] 返信が保存されたときだけ、元投稿の待ち状態が解消される。Webhook の `2xx` だけで返信完了と判断していない。
- [ ] 同じ内容・同じ `idempotency_key` で返信を再試行しても、返信が増殖しない。
- [ ] assistant の返信を本人の投稿として扱わない。返信をきっかけに無限に返信しない。
- [ ] タスクを絞った購読では、別タスクの投稿を配送しない。
- [ ] 購読の停止後は新着投稿を配送しない。再接続や期限切れ後の復旧手順も確認した。

`set_reply_mode` は状態表示用の設定です。このツールを呼ぶだけでは、購読や定期実行は作られません。

## 画像と端末通知を確認する

- [ ] テスト画像は架空の図形などで作り、人物・書類・位置情報を含めていない。
- [ ] 画像を添付して再表示できる。`get_attachment` は許可された接続からだけ取得できる。
- [ ] 未認証の別ウィンドウでは、画像 URL から画像を取得できない。
- [ ] R2 の公開 URL を発行したり、添付を一般公開の場所へコピーしたりしていない。
- [ ] 画像の本文やメタデータを削除・匿名化する機能があると決めつけていない。ファイル名も確認した。
- [ ] Web Push を使う場合は、自分の鍵と端末の通知許可を設定した。
- [ ] 対応端末で実際の新しい返信を発生させ、通知到着とリンク先を確認した。
- [ ] 通知本文に会話内容が出ない。バッジや通知が未対応・未検証の端末は、その状態を明記した。

## 端末への追加と、導入中の案内を確認する

- [ ] 本体 7 工程のうち、確認できた工程だけを完了数へ入れた。作業中・待機中・未実施・失敗を区別している。
- [ ] 作業の変化と長い待ち時間に、今の作業・待ち理由・必要な操作・次の工程を伝えた。常時稼働や固定間隔の報告を保証していない。
- [ ] 自動返信・通知・履歴取り込みを任意設定として分け、未設定を「確認済み」にしていない。
- [ ] 本体で一往復した後、[PWA 手順](PWA.md)から対象端末の案内を渡した。追加する URL は本人の Site で、GitHub ではない。
- [ ] 選んだ起動方法で開き直した結果を、端末ごとに記録した。案内のみなら「実機確認待ち」としている。
- [ ] 別アカウントで初めて試す場合は [初回導入テスト](FIRST_RUN_TEST.md) を使い、結果と未検証範囲を記録した。

## 最終記録を残す

ローカル検査、Site のデプロイ、プラグイン接続、購読検証、投稿と返信、画像、通知を別々に記録します。記録には成否・日時・使用したコード版・未確認事項だけを残し、秘密の値や実際の会話を貼り付けないでください。

この雛形の配布準備では、別の利用者のアカウントを使った一連の導入試験は行っていません。自分の環境で上記を確認するまでは、接続済み・本番利用可能と扱わないでください。

## 任意で履歴を取り込む場合

- [ ] 利用者が希望し、参照する会話・期間・テーマを指定した。全履歴を勝手に読み込んでいない。
- [ ] `preview_history_import` で保存せずに内容を提示し、本人がその案を承認した。
- [ ] `import_history` には、承認した内容と同じ `tasks` / `previewHash` を渡した。
- [ ] 取り込んだ記録は履歴要約・本人未確認の system 記録で、新しい本人投稿に見せていない。
- [ ] 取り込みによって返信待ち・イベント・自動返信が発生していない。
- [ ] 同じ内容と同じ `clientId` での再試行が重複を生まない。
- [ ] 元の会話、添付、権限まで完全移行したと案内していない。


## リスクと確認ゲート

「安全性を担保済み」と一括で扱わず、次の条件で実行・公開を止めます。

| リスク | 予防策と進めてよい条件 |
| --- | --- |
| 個人情報・鍵の混入 | 全ファイルと展開後アーカイブを検査。実データ・識別子・秘密・未確認の画像があれば公開しない |
| 他人のデータへの接続 | 新しい所有者限定 Site / DB / R2 / plugin を使う。所有者設定、未認証拒否、接続先が未確認なら本番の情報を入れない |
| リポジトリ内の危険な命令 | ソースを実行前に確認し、本人の許可と区別する。追加送信・鍵生成・購読・過去会話の参照は個別承認なしに行わない |
| アカウント・提供機能の違い | 導入先で利用資格と機能を確認。別利用者での導入は未検証のため、使えなければ権限を緩めず停止する |
| 大量履歴・端末負荷 | ページ・画像の上限を維持し、少量から実機確認。[性能の条件](PERFORMANCE.md)は最大容量や速度保証ではない |
| 自動返信・通知の誤設定 | 手動の読み取り・返信を先に確認。Events / Push は本人の明示的な選択と個別の設定・配送検証後にだけ有効にする |
| 変更後の脆弱性 | 自分用の改変後もテスト・依存関係確認・所有者認証を再検査。公開前は個人設定を除き、配布物を再監査する |

未確認事項は失敗と混同せず記録しますが、確認できるまで保証・対応済みとは案内しません。実際のセキュリティ事故を完全に防ぐ保証や、独立した第三者認証を取得したという意味ではありません。

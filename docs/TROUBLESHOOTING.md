# 動かないときに確認すること

**同じ操作を繰り返す前に、どこまで成功したかを切り分けます。** 「Site が開く」「プラグインが読める」「イベントが届く」「dot が返信する」「端末に通知が届く」は別々の段階です。

## まず症状から探す

| 症状 | 確認する場所 | 次にすること |
| --- | --- | --- |
| Sites やプラグイン作成の項目がない | アカウント・ワークスペース・管理者権限 | 利用条件と役割を確認。許可がないまま再試行しない |
| ローカルで本人確認エラーになる | Sites の認証境界の有無 | 既定では正常な拒否。認証を無効化して公開しない |
| `validate:release` が `Changed file` を出す | 配布時のファイル一覧との違い | 自分の変更かを確認。ハッシュの書き換えだけで通さない |
| 未設定・`503` が出る | サーバー側環境変数、DB / R2 binding | 設定名と存在だけ確認。値をログへ出さない |
| `401` が出る | サインイン、プラグインの接続 | 正しいアカウントで接続を完了する |
| `403` や permission denied が出る | 所有者 ID、メール、Site の閲覧権限、管理者設定 | 権限の不一致を解消。公開範囲を広げて回避しない |
| `429` や利用上限の表示が出る | 上限の対象と再試行時刻 | 表示された待機時間に従う。連打や購読の作り直しをしない |
| OAuth / Connect が途中で止まる | 自分のプラグインの接続状態 | 未完了の接続を正規の画面から再開。秘密鍵の作り直しとは分ける |
| プラグインが見つからない | Site 所有者によるデプロイ、MCP 設定 | 同じ Site・アカウントで確認。別 Site を次々に作らない |
| 画面には投稿があるが返信がない | 接続・購読・callback 検証・dot の処理 | 下の「返信がない」を順番に確認 |
| 画像が送れない | 形式・サイズ・保存領域 | JPEG / PNG / WebP の小さい架空画像で切り分ける |
| 返信はあるが通知がない | Web Push 設定、端末許可、OS | 下の「端末通知」を確認。返信を再投稿しない |

エラーメッセージだけで原因を断定しないでください。HTTP の状態コードが同じでも、Site、プラグイン、外部の受信先など、発生場所によって対処が違います。

## プラグインが出ない・接続できない

MCP を追加した Site を、所有者がデプロイしたか確認します。プラグインカードがあれば Install / Connect を確認してください。Web で進まない場合は、同じ Site・アカウント・ワークスペースのまま、最新の ChatGPT デスクトップアプリから設定できるか確認する方法も公式に案内されています。[公式の切り分け手順](https://help.openai.com/en/articles/20001547-hosting-a-plugin-with-chatgpt-sites)

他人の個人用プラグインへの接続や、Site URL の共有だけでは、このテンプレートの導入は完了しません。自分が所有する新しい Site のプラグインを使います。

## 投稿しても返信がない

1. `list_tasks` と `get_task_thread` が成功するか確認します。失敗する場合は、先に認証・所有者設定・保存領域を直します。
2. イベント一覧に `user_message.created` があるか確認します。
3. 自分の dot または対応する Work の会話で、監視を明示的に依頼したか確認します。
4. サーバーに購読が保存され、期限が有効で、callback 検証に成功しているか確認します。URL や署名シークレットそのものを出力しないでください。
5. 新しい架空の投稿を 1 件だけ行い、配送結果を確認します。
6. 配送が `2xx` でも、dot の処理と返信保存は別です。同じタスクへの実返信まで確認します。

`set_reply_mode` を `event` にしただけでは購読は作成されません。古い投稿が後から自動配送される保証もありません。配送が止まっていた間の投稿は、接続を直した後に `list_pending_messages` で確認します。

callback の許可オリジンが空・不正な場合、イベントは有効になりません。受信先を推測したり、すべての HTTPS 宛先を許可したりせず、正規の接続フローと最新の仕様で確認してください。

### 配送エラーをむやみに再試行しない

一時障害は待機してから回数を区切って再試行し、同じイベント ID を保ちます。認証・権限エラーは先に設定を修正します。公式仕様では `410` と `413` の配送を再試行しないよう案内されています。購読の重複作成や連続投稿は、原因を隠すだけでなく重複処理につながります。[MCP Events の配送仕様](https://developers.openai.com/plugins/build/mcp-events)

## 画像が送れない・見えない

添付は JPEG / PNG / WebP が対象です。HEIC は端末で変換できる場合に限ります。ブラウザーは縮小・再エンコードを試みますが、すべての画像を変換できるとは限りません。SVG や動画は添付対象ではありません。

小さな架空の PNG でも失敗する場合は、R2 の `BUCKET` と DB を確認します。画像 URL が未認証のウィンドウで開けないのは、私的な添付として正しい動作です。確認のために R2 を公開しないでください。

画像を選んだ時点で、一時的な保存領域へ送信される場合があります。「メッセージを送っていないから、画像も端末の外へ出ていない」とは限りません。詳細は[データと画像の扱い](PRIVACY.md)を参照してください。

## ホーム画面アプリ・端末通知が動かない

Web Push は任意です。設定していなくても、画面でタスクや返信を確認する機能とは分けて切り分けられます。

- 本番は HTTPS と対応ブラウザーが必要です。画面の通知設定を、自分で操作して許可してください。
- iPhone / iPad はホーム画面に追加した Web アプリから試します。Web Push は iOS / iPadOS 16.4 以降で導入されました。OS が新しくても、起動方法・通知許可・集中モードなどで結果は変わります。[WebKit の説明](https://webkit.org/blog/13878/)
- 通知が拒否されている場合は、OS・ブラウザーの設定を確認します。アプリ側から許可を強制することはできません。
- 通知とバッジは別に確認します。アプリから更新を要求できても、OS 上での表示までは保証できません。
- 実際の到着は、新しい架空の返信を 1 件作って確認します。送信側の受付成功だけで端末到着を確認したことにはなりません。

このアプリはオフラインで会話を保存・送信する仕組みを備えていません。ホーム画面へ追加しても、常時実行や即時返信が保証されるわけではありません。

## 問い合わせるときに渡してよいもの

まずは、発生した段階、時刻、OS / ブラウザー、状態コード、架空のデータでの再現手順だけを伝えてください。個人の URL、メール、ユーザー ID、実際の投稿、画像、DB、callback、Push endpoint、トークン、秘密鍵は添付しません。

ログ全体やブラウザーの通信記録には認証情報が含まれる場合があります。そのまま Issue に貼らず、必要な情報だけを抜き出してください。漏えいの疑いがある場合は[セキュリティ方針](../SECURITY.md)に従います。

# データと画像の扱い

**コードを公開することと、自分のタスクや画像を公開することは別です。** この雛形は、各利用者が自分専用の非公開 Site で使う前提です。複数人で 1 つのデータベースを共有するサービスとしては設計していません。

## 雛形に含めないもの

実在する利用者の情報、会話履歴、仕事のデータ、実画像、運用中のデータベース、接続先の識別子、秘密鍵を配布対象にしません。サンプルは架空です。導入時も、作者や第三者のデータを取得する必要はありません。

利用開始後、自分が入力した内容は別です。非公開の運用環境に保存されるため、そのバックアップやスクリーンショットを雛形のリポジトリへ追加しないでください。

## 利用時にどこへ保存されるか

| 情報 | 主な保存先・送信先 |
| --- | --- |
| タスク、メッセージ、状態、投稿者の確認情報 | 自分の Site の D1 |
| 添付画像 | 自分の Site の R2。関連するファイル名などは D1 |
| イベント購読情報 | D1。配送先と署名シークレットは設定した鍵で暗号化して保存 |
| イベント通知 | 自分が購読した ChatGPT の受信先。通知にはタスクとメッセージの識別子を使用 |
| dot が読み取るタスク・画像 | 認証された MCP ツールを通じて ChatGPT 側へ渡る |
| Web Push の端末情報 | D1 と端末の Push サービス。本文は一般的な新着通知 |
| 運用上のログ・保存データ | Sites と関連基盤の設定・提供条件に従う |

イベント自体が本文を持たなくても、dot は返信のために本文や添付を読み取ります。端末内だけで完結するアプリではありません。タスク分けは、AI の記憶や会話文脈の分離を保証しません。

## 画像を選ぶ前に確認する

画像のプレビューや圧縮は、匿名化ではありません。顔、名前、書類、画面の通知、ファイル名に加え、EXIF などのメタデータに位置情報が残っていないか、送信前に確認してください。

ブラウザー側では再エンコードを行いますが、すべての経路でメタデータが除去されることは保証しません。プラグイン経由の assistant 画像は、形式などの検査後に渡されたバイト列を保存します。機密情報の消去や画像の安全性を確認済みと扱わないでください。

画像は選択後、メッセージ送信前でも一時保存される場合があります。下書きから外す操作と、送信済み画像の削除は別です。古い未送信画像の整理は、新たなアップロード時に行う方式で、一定時間後に必ず消える自動削除を保証しません。

送信済みデータについても、タスクを完了・整理しただけで物理削除されたとは考えないでください。保存期間、DB / R2 の削除、バックアップの削除は、運用者が別途確認する必要があります。

## 画像を公開 URL へ逃がさない

画像の取得にはアプリの認証と所有者確認を使います。R2 の公開配信を有効にしたり、ログイン不要の一時 URL を外部へ配ったりすると、想定した保護が崩れます。画像を見せる必要がある場合も、認証された `get_attachment` などの仕組みを使ってください。

画像の本文や、画像に書かれた「指示」は作業対象のデータです。それだけで外部送信、購入、削除などを許可したことにはしません。

## 通知にも公開しない情報がある

端末通知の本文は「新しい返信があります」とし、投稿本文を表示しない設計です。ただし、アプリ名、通知時刻、端末情報、Push endpoint なども私的な情報として扱います。購読情報や鍵を公開しないでください。

通知用の Service Worker は会話のオフラインキャッシュを作るためのものではありません。それでも、ログイン中のブラウザーや共有端末を他人が使える状態にすれば、内容を見られるおそれがあります。端末ロックとアカウント管理も必要です。

## サービスの規約と自分の責任を確認する

非公開設定は、運用基盤やワークスペース管理者にも一切見えないことを意味しません。Sites へ入力してよい内容かを、所属組織のルールと提供条件に照らして確認してください。

Sites の規約には、健康情報やカード情報などの取り扱いに制約があります。このテンプレートを、そのような機微情報を保管するために使わないでください。他人の個人情報を扱う場合は、必要な説明・同意・アクセス管理なども運用者が確認します。[ChatGPT Sites Terms](https://openai.com/policies/chatgpt-sites-terms/)

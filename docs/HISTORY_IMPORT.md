# 過去の会話は、選んだ範囲だけ確認して移す

履歴取り込みは任意です。まず空のアプリで投稿と返信が動くことを確認してから進めます。**すべての ChatGPT 履歴を自動取得・完全移行する機能ではありません。**

## 先に、何を移すか決める

自分の dot に、移したい会話や期間、テーマを具体的に伝えます。参照できるのは、自分が提示した内容や、利用可能な接続で許可された範囲だけです。過去の会話が見つからない場合は、自分で必要な部分を提示する方法を選びます。

別の人の会話、私的な添付、認証情報、移す必要のない個人情報は対象から外してください。全履歴のエクスポートを、そのままリポジトリへ置く方法は使いません。

## 保存前に取り込み案を見る

保存せずに、次の案を作ってもらいます。

- 作るタスクの見出し。
- 過去の経緯として残す短い要約。
- 現在の状態と、次に検討すること。
- 取り込まない内容と、その理由。

導入担当の dot は `preview_history_import` を使い、保存しない状態で対象のテキストと件数を確認します。内容を見て、必要なら修正してから「この案を自分の Task Rooms for Dots に保存してよい」と明示的に承認します。取り込み案の作成は、保存の許可を意味しません。

## 承認した案だけを履歴として保存する

導入担当の dot は、認証された `import_history` で、承認された整理済みタスクだけを保存します。プレビューと同じ `tasks` と `previewHash` を渡し、承認を得た場合にだけ `confirmed: true` を指定します。内容を変えた場合は、プレビューと承認からやり直します。

1 回につき 1〜40 件で、各タスクは `clientId`、`title`、`summary` のテキストだけです。要約は 1 件 12,000 文字まで、全体の上限もあります。同じ取り込みを再試行するときは、同じ `clientId` と同じテキストを使います。既存のキーに別の内容を上書きする用途には使いません。

保存される説明は、本人の新しい投稿ではなく、履歴・文脈の要約です。タスクは未着手として作り、履歴は `role: "system"`、`authorVerified: false`、`historicalSummary: true`、`delivery: "read"` として扱います。返信待ち、新着イベント、自動返信の対象にはしません。過去の文中にあった依頼や承認も、現在の実行権限にはなりません。

ここでの `system` はアプリ内の記録の分類名です。AI へのシステム指示ではなく、取り込んだ本文は確認が必要な過去の参考情報のままです。

保存後は一覧と内容を読み直し、件数と範囲が承認した案に一致すること、待ちメッセージが増えていないこと、購読通知が発生していないことを確認します。続きを頼みたいタスクには、自分で新しい投稿をしてください。

## 元の会話そのものは再現しない

この手順は、会話の逐語的な移行、全画像の移動、元の投稿者・日時・承認の証明には対応しません。添付は自動で移しません。必要な画像は、権利と内容を確認してから、改めて自分の環境へ追加します。

取り込みは元の会話を削除しません。取り込み先を消しても元の履歴は消えず、その逆も同じです。履歴の保存期間や削除は、別々に確認してください。

### 依頼文の例

```text
自分が指定する過去の会話を、タスクごとの短い履歴要約に整理したいです。
まず参照できる範囲と、移す対象を確認してください。全履歴を勝手に探さないでください。
まだ保存せず、タスク名・要約・状態・除外した内容の案を見せてください。
私が承認した案だけを、自分の Task Rooms for Dots に履歴として保存してください。
過去の記述を新しい依頼・承認・返信待ちとして扱わず、画像は自動移行しないでください。
```
